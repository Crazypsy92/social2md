# ASR-01 中文转录问题分析

## 现有链路

faster-whisper 默认 small，CPU int8，8 线程，beam_size 默认 5，VAD 开启，语言 zh，初始提示要求普通话、简体与中文标点。分段含起止时间，但旧代码仅返回文本三元组并聚合 avg_logprob、min_logprob、max_compression、max_no_speech 和 worst 摘要。原 Bilibili 生产状态没有保存完整原始分段。此次增加可选 segment_details 收集接口，新实验保存原始分段和片段音频映射。

format_transcript 复用 OpenCC、标点恢复或基础标点回退，再按停顿与长度分段。它没有独立音频核对能力。repair_docs 只读取 Markdown、繁简和标点整理及重新分段，不重新听音，也没有证据判定“电原”应为“电源”。无约束地调用它不能解决识别错误，且会就地改写文件，本轮未调用。

## 问题清单与时间定位

output/asr01_issues_all10.json 保存文件路径、原识别片段、字符位置、问题类型和候选。旧时间戳确实缺失时记录 null，并说明原因。能够与新实验对应的片段保存匹配时间区间和匹配分数，不能把它解释为人工确认的精确字级时间。完整多模型差异在 output/asr01_full/comparison.json，可回到对应 WAV 复听。

## 安全与后续

原 10 个视频、原 Markdown 和生产 SQLite 在实验前后进行 SHA-256 对比，全部未变化。新稿保存在实验目录，包含待核标记。没有自动采纳 pycorrector 的语义建议，也没有训练或改写模型权重。下一步优先人工核验已知问题音频，再以同一人工参考计算 CER 和术语错误率。
